# ADR-002: 내부 패키지는 compiled ESM 단일 포맷(tsc → dist)

## Status
Accepted (2026-09-16)

## Context
Turborepo는 내부 패키지에 just-in-time(TS 소스를 그대로 export) 또는 compiled(dist 출력) 전략을 제시한다. 이 저장소의 소비자는 Node ESM(Nest 12, 번들러 없이 `node dist/main.js`), Metro(RN), jest-expo(babel-jest, Jest 29), Vitest 4로 갈린다. Node 24의 내장 타입 스트리핑은 경로에 `node_modules`가 포함된 `.ts`를 거부하며 데코레이터 문법도 처리하지 못한다(PRD §1.4). 관련: ADR-001(모노레포), ADR-004(API ESM).

## 결정
- `packages/schemas`는 `"type": "module"`이며 `tsc`(module/moduleResolution `nodenext`)로 `dist/`에 ESM + `.d.ts`를 출력한다.
- `exports`의 `.` 엔트리는 `types`(`./dist/index.d.ts`)를 `default`(`./dist/index.js`)보다 앞에 둔다.
- 소비자는 turbo `^build` 의존으로 dist 존재를 보장한다.
- 소스 상대 import는 `.js` 확장자를 쓴다.

## 이유
- JIT 전략은 Nest 런타임(번들러 없는 Node ESM)에서 불가하다.
- API가 ESM(ADR-004)이므로 패키지도 ESM이면 CJS↔ESM interop 계층이 없다.
- Metro는 ESM을 네이티브로 처리하고, jest-expo는 워크스페이스 심링크의 실경로(`node_modules` 밖)를 babel로 변환하므로 CJS 출력이 필요 없다.
- 단일 포맷은 dual-build 도구(tsdown/tsup) 없이 tsc만으로 끝난다.

## 트레이드오프
- 소비 전 반드시 빌드해야 한다 — dev 루프에 watch가 필요하고, 단일 패키지 `--filter` 실행은 의존 패키지를 자동 빌드하지 않으므로 AC가 schemas build를 명시해야 한다.
- `exports`가 있으면 Metro는 플랫폼 확장자(`.ios.ts`)를 무시하므로 플랫폼 분기는 `Platform.select`로 한다.
- `types`를 `src`가 아닌 `dist`로 가리켜야 TS 6에서 소비자 rootDir가 오염되지 않는다.
