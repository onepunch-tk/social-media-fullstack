# ADR-004: NestJS 12 ESM + Vitest(프레임워크 기본 템플릿)

## Status
Accepted (2026-09-16)

## Context
NestJS 12는 모든 코어 패키지가 ESM-only(`"type": "module"`)이며 `nest new`의 기본 템플릿이 ESM + Vitest다. CJS + Jest 템플릿은 TTY 프롬프트에서만 선택 가능하고, 비대화(헤드리스) 세션에서는 프롬프트 없이 ESM으로 생성된다(PRD §1.4 격리 헤드리스 세션 제약). CJS를 고집하면 Nest 12 ESM 패키지를 Jest가 `require(esm)`하기 위해 Jest ≥30.4 + `--experimental-vm-modules` + Node ≥24.9가 필요하다.

## 결정
- `apps/api`는 Nest 12 ESM 템플릿을 그대로 채택한다: `"type": "module"`, tsconfig `module/moduleResolution: nodenext`, `.js` 확장자 import, `vitest` + `vite-tsconfig-paths`, `vitest.config.e2e.ts`.
- 템플릿의 oxlint/prettier는 Biome(ADR-009)으로 교체한다.

## 이유
- 프레임워크 기본 경로라 헤드리스 생성이 결정적이고, 향후 Nest 문서·마이그레이션 가이드와 정렬된다.
- ESM 공유 패키지(ADR-002)와 interop이 0이다.
- Vitest 4는 TS 데코레이터 메타데이터를 템플릿 설정만으로 처리한다.

## 트레이드오프
- 모바일(jest-expo, Jest 29)과 테스트 러너가 갈린다(ADR-011).
- 소스 상대 import에 `.js` 확장자 규율이 필요하다.
- `isolatedModules` + `emitDecoratorMetadata` 조합에서 데코레이터 시그니처의 타입은 `import type`이어야 한다(TS1272).
- tsconfig `paths`는 tsc emit에서 재작성되지 않으므로 런타임 별칭은 package.json `imports`로 따로 보장해야 한다(ADR-005).
