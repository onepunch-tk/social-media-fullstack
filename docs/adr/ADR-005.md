# ADR-005: NestJS ddd-hexagonal + CQRS 수직 슬라이스, `health`가 템플릿 슬라이스, `#` 별칭

## Status
Accepted (2026-09-16)

## Context
도메인이 미정이라 첫 바운디드 컨텍스트가 없다(PRD §1.4, OQ-1). 그래도 이후 도메인이 같은 모양으로 복제될 구조가 지금 필요하다(PRD §1.2). Nest CQRS 12는 `CqrsModule.forRoot()`가 전역 등록이며 `Query<T>` 제네릭 타이핑을 지원한다. ESM Node 런타임은 tsconfig `paths`를 모르지만 package.json `imports`(`#` 서브패스)는 Node·TS(nodenext)·Vite 모두 해석한다. 관련: ADR-004.

## 결정
- 슬라이스 단위는 `src/{slice}/` 아래 application/domain/infrastructure/presentation 4레이어 + `{slice}.module.ts`다. 포트는 application의 `ports/`(Symbol 토큰 + 인터페이스), 조회는 `queries/` + `queries/handlers/`, 컨트롤러는 QueryBus/CommandBus 디스패치만 한다.
- 비도메인 `health` 슬라이스(`GET /health`, `DatabasePingPort`)를 첫 템플릿으로 둔다.
- 컨텍스트 경계를 넘는 import는 `#shared/*`·`#health/*` 별칭만 쓴다. (2026-09-22 수정, ADR-004) tsconfig `paths` 한 곳에만 선언한다 — Nest CLI가 `paths`를 swc에 넘겨 emit 시 상대경로로 재작성하므로 package.json `imports`는 없다.
- 전역 1회 등록(`CqrsModule.forRoot`, `ConfigModule.forRoot`, DB 모듈)은 `app.module.ts`에서만 한다.

## 이유
- 도메인 도착 전에 레이어 규칙·결선 위치·별칭 규칙이 실제로 빌드·테스트되는 예시가 있어야 격리 세션이 흉내낼 수 있다.
- CQRS 버스는 컨트롤러를 얇게 유지해 presentation이 포트를 직접 만지지 않게 한다.
- `#` 별칭은 추가 도구(tsconfig-paths, SWC 재작성) 없이 Node 표준으로 런타임 해석된다.

## 트레이드오프
- 단일 엔드포인트에 CQRS·포트·어댑터·모듈은 과잉으로 보인다(템플릿 가치로 감수).
- 런타임 별칭 해석이 swc 빌더에 묶인다(plain `tsc` emit은 별칭을 재작성하지 않는다).
- `health`는 도메인이 아니므로 향후 진짜 도메인과 혼동되지 않게 이름을 유지한다.
