# ADR-011: 테스트 러너 = 프레임워크 기본값(api Vitest / mobile jest-expo / packages bun test)

## Status
Accepted (2026-09-16)

## Context
api는 Vitest(Nest 12 ESM 템플릿, ADR-004), mobile은 jest-expo(Jest 29 기반, `@react-native/jest-preset` 필요). `expo-router/testing-library`의 `renderRouter`는 RNTL 13.x 동기 API를 전제하며 14.x는 `render`가 async·`test-renderer`로 교체되어 미호환이다. `bun add jest`는 30.x를 뽑아 jest-expo와 불일치한다. 프레임워크가 없는 `packages/schemas`는 러너가 정해져 있지 않다.

## 결정
- api = vitest + @nestjs/testing + supertest(단위 `*.spec.ts`, e2e `test/*.e2e-spec.ts`, 실 DB).
- mobile = jest-expo ~57 + jest ~29.7.0 + @testing-library/react-native ~13.3.3(핀).
- packages = `bun test`(설정 0).
- 루트 `test`는 `turbo run test`.

## 이유
- 각 프레임워크가 검증한 조합이 헤드리스 세션에서 가장 결정적이다.
- 순수 TS 패키지는 bun test가 설정 없이 가장 가볍다.
- 통일 러너(bun test 전체·vitest 전체)는 RN preset 부재·데코레이터 메타데이터 미검증으로 위험하다.

## 트레이드오프
- 세 러너 공존(jest 29·vitest 4·bun test) — 작성 규칙이 패키지마다 다르다.
- 루트에서 `bun test`를 실행하면 다른 러너의 파일을 잘못 집으므로 금지한다.
- RNTL 14 마이그레이션은 expo-router 지원 후로 미룬다.
