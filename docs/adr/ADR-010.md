# ADR-010: TypeScript ~6.0 고정(TS 7 보류)

## Status
Accepted (2026-09-16)

## Context
npm latest는 TypeScript 7.0.2(Go 네이티브 컴파일러)지만 @nestjs/cli 12는 `typescript ~6.0.2`, Expo 57 템플릿은 `~6.0.3`을 고정한다(PRD §1.4, OQ-2). TS 6.0은 `types` 기본값 `[]`, `rootDir` 기본이 tsconfig 디렉터리, `baseUrl` deprecated(`ignoreDeprecations` 없이는 에러), `esModuleInterop: false` 금지, `moduleResolution: classic` 제거 등 파괴적 변경을 담는다.

## 결정
- 전 패키지 `typescript ~6.0.3` 고정(각 패키지 devDependency로 선언).
- 공유 `packages/typescript-config/base.json`은 strict 계열만 담고 `module/moduleResolution/target/types/rootDir/outDir`는 패키지별로 명시한다.
- `baseUrl` 전면 금지(`paths`만).
- TS 7은 Nest CLI·Expo 템플릿이 지원하면 재검토한다.

## 이유
- 두 프레임워크의 검증 범위 안에 머문다.
- TS 6 기본값 변화는 `types`·`rootDir`를 명시하지 않으면 조용히 빌드를 깨므로 base에 넣지 않고 각 패키지가 소유하게 한다.

## 트레이드오프
- TS 7의 컴파일 속도 이점을 포기한다.
- `types`를 패키지마다 반복 선언한다.
- `baseUrl` 없이 `paths`만 쓰므로 상대 형태 `./src/...` 매핑 규율이 필요하다.
