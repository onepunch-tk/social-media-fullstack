# ADR-008: stylo-native(자작 순수 JS 스타일 라이브러리) 단일 채택

## Status
Accepted (2026-09-16)

## Context
사용자가 직접 만든 `stylo-native` 1.0.0(2026-09-14 공개)을 요구했다(PRD §12.2). `StyleSheet.create` 멘탈 모델 + 테마·변형·캐시, 순수 JS, 의존성 0, Babel/Metro 플러그인 없음, peer `react-native >= 0.82`(New Architecture 전용), `__DEV__` 전역 필요(Metro·jest-expo가 정의). API: `defineThemes({light, dark}, 'light')` → `{handles, store}`, 루트 `<ThemeProvider store={store}>`, `createStyleSheet`(정적/테마 팩토리) + `useStyles`, `variants`, `store.set(name)`으로 전환, `StyloTheme` 모듈 증강.

## 결정
- 모바일 스타일링은 stylo-native 단일이다.
- 테마 정의는 `src/shared/presentation/theme/theme.ts` 한 파일에서 `defineThemes`를 1회만 호출한다.
- `ThemeProvider`는 루트 레이아웃에서 QueryClientProvider 안쪽에 마운트한다.
- Appearance 동기화는 `useEffect`에서만 한다.

## 이유
- 사용자 소유 라이브러리라 스캐폴드가 곧 dogfooding이다.
- 플러그인·네이티브 코드가 없어 Expo Go·jest-expo·정적 export에서 추가 설정이 0이다.
- RN 0.86(SDK 57)은 New Architecture 기본이라 peer 조건을 만족한다.

## 트레이드오프
- 커뮤니티 검증이 없고 unistyles/NativeWind 같은 생태계(문서·예제)가 없다.
- New Architecture 전용이다.
- 테마 sheet는 불투명(직접 프로퍼티 접근은 컴파일 에러, 스프레드 시 브랜드 상실)이라 `useStyles` 규율이 필요하다.
- `defineThemes` 중복 호출·render 중 `store.set`은 dev 경고/에러다.
