# ADR-001: Turborepo 2 + bun workspaces 모노레포, hoisted linker

## Status
Accepted (2026-09-16)

## Context
모바일(Expo)·API(Nest)·공유 Schema를 한 저장소에서 관리해야 하고 패키지 매니저는 bun 1.3.14로 확정됐다(PRD §1.4, §12.5). bun 1.3.2+는 새 워크스페이스를 isolated(pnpm식 심링크 스토어) linker로 기본 설치한다. Expo는 SDK 54부터 isolated를 지원하고 SDK 55+는 monorepo 앱에 `autolinkingModuleResolution`을 자동 적용하지만, RN 자동링킹·Metro·jest-expo가 가장 오래 검증한 경로는 hoisted다. turbo 2.10은 bun을 네이티브 지원(Stable)하되 `packageManager: "bun@x.y.z"` 선언과 텍스트 `bun.lock`을 요구한다.

## 결정
- Turborepo 2.10 + bun workspaces(`apps/*`, `packages/*`)를 채택한다.
- 루트 `bunfig.toml`에 `[install] linker = "hoisted"`를 명시하고, 루트 package.json에 `packageManager: "bun@1.3.14"`를 선언하며 `bun.lock`을 커밋한다.
- task 그래프는 build/lint/typecheck/test/dev이며 소비자 task는 `^build`에 의존한다.
- 루트 devDependencies는 repo 도구(turbo, biome, 공유 config)만 둔다.

## 이유
- 단일 lockfile·캐시된 task 그래프·`--filter`로 격리 세션의 AC가 단순해진다.
- hoisted는 RN/Expo 툴체인이 가장 오래 검증한 형태라 스캐폴드 단계의 미지 변수를 줄인다.
- nx/pnpm 대비 설정량이 최소다.

## 트레이드오프
- hoisted는 phantom dependency를 허용한다 — 각 패키지가 자기 의존을 선언하는 규율로 보완한다.
- turbo 캐시는 `EXPO_PUBLIC_*` 같은 인라인 env 변화를 `globalEnv`/`inputs`에 선언해야 인지한다.
- bun은 `engines.node`를 강제하지 않아 Node 버전 불일치를 조용히 통과시킨다.
