# ADR-006: drizzle-orm + postgres.js on PostgreSQL 16(로컬 컨테이너 재사용)

## Status
Accepted (2026-09-16)

## Context
소셜 미디어는 관계형(FK·인덱스)이 필요하다. 사용자 로컬 docker에 PostgreSQL 16 컨테이너(`postgres`, localhost:5432, postgres/postgres)가 이미 있고 compose를 만들지 않길 원한다(PRD §1.3, §1.4). 로컬 `psql`은 없고 `docker exec postgres psql`만 가능하다. drizzle 공식 사이트는 1.0-rc 문서를 기본으로 보여주지만 안정 버전은 drizzle-orm 0.45.x / drizzle-kit 0.31.x다.

## 결정
- drizzle-orm `~0.45.2` + `postgres`(postgres.js) `^3.4.9` 드라이버, drizzle-kit `~0.31.10`(설정 파일만, 마이그레이션은 Deferred).
- DB명 `social_media`, 접속은 `DATABASE_URL` env. DB 생성은 `docker exec postgres psql`로 멱등 preflight.
- DB 클라이언트는 Nest 전역 모듈의 provider가 소유하고 `onModuleDestroy`에서 `sql.end()`로 풀을 닫는다.
- Health는 `select 1` ping.

## 이유
- drizzle은 스키마가 TS 코드라 ADR-002/003의 타입 흐름과 맞고 SQL에 가깝다.
- postgres.js는 네이티브 빌드 없는 순수 JS 드라이버라 bun 설치에서 postinstall 이슈가 없다.
- 기존 컨테이너 재사용이 compose보다 사용자 환경에 맞는다.

## 트레이드오프
- 컨테이너 이름·자격증명이 환경 가정으로 남는다(`.env.example`·AGENTS.md에 기록).
- postgres.js 풀은 `idle_timeout 0`이 기본이라 명시적으로 닫지 않으면 e2e 프로세스가 hang한다.
- drizzle 1.0-rc 문서와 0.45 API가 다르므로 버전 고정이 필수다.
- `CREATE DATABASE`는 비멱등이라 존재 검사가 필요하다.
